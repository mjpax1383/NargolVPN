# منابع: افزودن، حذف و سالم نگه داشتن

همه‌چیز در `tester/sources.json` است. دو نوع منبع داریم:

```json
{
  "telegram_channels": ["v2ray_configs"],
  "raw_urls": ["https://raw.githubusercontent.com/OWNER/REPO/main/file.txt"],
  "timeout_sec": 20,
  "max_bytes_per_source": 2500000,
  "max_per_source": 700
}
```

## ۱. کانال تلگرام

فقط **slug** را بنویسید (بدون `@` و بدون لینک). مثلاً برای `https://t.me/v2ray_configs` مقدار `v2ray_configs`.

قبل از اضافه کردن، در مرورگر `https://t.me/s/<slug>` را باز کنید: باید آخرین پست‌ها را ببینید.
اگر صفحه خالی است یا «Preview channel» نشان می‌دهد، کانال عمومی نیست و قابل خواندن بدون بات هم نیست.

**محدودیت‌ها:**

- فقط پست‌های اخیر صفحهٔ پیش‌نمایش خوانده می‌شود (حدود ۲۰ پست آخر). برای آرشیو، لینک صفحهٔ تکی پست‌ها لازم است که در پروژه پیاده نشده.
- کانال‌هایی که لینک را در عکس می‌گذارند خوانده نمی‌شوند.
- تلگرام ممکن است بعد از چند درخواست پشت‌سرهم، صفحه را محدود کند؛ برای همین چند ثانیه فاصله طبیعی است.

## ۲. فید خام

هر آدرسی که متن ساده یا HTML برگرداند. سه حالت پشتیبانی می‌شود:

1. فایل متنی ساب با لینک‌های خط‌به‌خط.
2. فایل base64 (کل محتوا یک بلوک base64) → خودکار باز می‌شود.
3. HTML با بلوک‌های base64 داخلش (بعضی سرویس‌ها) → هم متن و هم بلوک‌ها اسکن می‌شوند.

اگر فید بزرگ‌تر از `max_bytes_per_source` باشد، فقط ابتدای آن خوانده می‌شود. برای فیدهای چند مگابایتی این عدد را بالا ببرید.

## ۳. `max_per_source`

هر منبع حداکثر این تعداد کانفیگ یکتا تحویل می‌دهد (پیش‌فرض ۷۰۰). بدون این سقف، یک فید با ۱۲٬۰۰۰ لینک
کل استخر را قبضه می‌کند و بقیهٔ منابع هرگز شانس تست پیدا نمی‌کنند. قبل از برش، نمونه‌برداری تصادفی انجام می‌شود.

## ۴. سالم نگه داشتن

```bash
python tester/agent.py sources
```

برای هر منبع `status` و تعداد لینک را چاپ می‌کند. یا در GitHub: **Actions → probe-sources → Run workflow**
و جدول سلامت در Summary همان اجرا. هر منبعی که چند دوره پشت‌سرهم `0 links` داد را حذف کنید.

## ۴.۵. چه چیزی از این منابع انتخاب می‌شود؟

همهٔ لینک‌ها تست می‌شوند، ولی ساب نهایی ترکیب‌محور است: در `tester/score.py` دیکشنری `PROTO_SHARE`
سهم SS (۱۵٪) و Trojan (۲۰٪) را محدود می‌کند و بقیه به VLESS/VMess می‌رسد؛ `diversify()` هم
حداکثر ۸ سرور از هر کشور برمی‌دارد تا پرچم‌ها متنوع بمانند. اگر منبعی فقط یک پروتکل دارد،
حداکثر همان سهمش از ساب را می‌گیرد. علت این سخت‌گیری: سرورهای SS ارزان‌تر و فراوان‌ترند و
بدون سقف، ساب از SS پر می‌شد (قبلاً ۲۶٪ کل ساب و بخش اول حتی بیشتر).

خانوادهٔ ایران دو حالت دارد: اگر اجرای `--vantage ir` واقعاً از داخل ایران تست کرده باشد،
همان نتایج استفاده می‌شود؛ وگرنه `iran_fit()` بر اساس شکل کانفیگ (TLS/Reality، پورت‌های CDN،
ترانسپورت ws/gRPC، SNI دامنه‌ای) یک لیست پیشنهادی می‌سازد و صفحه/دیجست صریح می‌گویند که این
لیست از داخل ایران تست نشده.

## ۵. کیفیت مهم‌تر از کمیت است

- ۱۰ منبع زندهٔ پرترافیک بهتر از ۵۰ منبع نیمه‌مرده است: هر منبع مرده حدود ۲ ثانیه از هر اجرا را می‌خورد.
- منبعی که کانفیگ‌هایش نرخ بقای بالاتری دارد، ارزش تست بیشتری دارد؛ فعلاً ۷۵٪ ظرفیت تست هر ساعت به VLESS/VMess می‌رسد و بقیه تصادفی است (`FRESH_PREFERRED_SHARE` در `tester/agent.py`).
- اگر منبعی خیلی بزرگ است و نرخ بقای پایینی دارد، `max_per_source` آن را کم کنید.

## ۶. نکتهٔ حقوقی

این پروژه فقط محتوای **عمومی** را می‌خواند و مانند یک موتور جست‌وجو دوباره منتشر می‌کند؛ هیچ دور زدن احراز هویت،
هیچ اسکرپ حساب خصوصی و هیچ حمله‌ای در کار نیست. با این حال:

- قبل از عمومی کردن کانال، قوانین کشور خودتان و قوانین تلگرام را در نظر بگیرید.
- هر منبعی که صاحبش صریحاً بازنشر را منع کرده، حذف کنید.
- لینک منبع را در توضیحات کانال ذکر کنید؛ اعتبار کار متعلق به جمع‌کننده‌های اصلی است.
